TWA App Rejected on Google Play? 5 Proven Fixes & Migration Guide (2026)

Published December 2024 • Updated for 2026 Google Play Policy • 20 min read • By Senior Android QA Lead
⚡ Quick Answer: Fixing TWA Google Play Rejections

Trusted Web Activity (TWA) apps are typically rejected for: 1) Digital Asset Links verification failures (causing Chrome's address bar to display), 2) Webview / Web Wrapper Minimum Functionality violations, 3) Google OAuth redirecting out of the app, or 4) lack of offline error handling.

The Solution: Either fix your assetlinks.json using the Google Play App Signing SHA-256 fingerprint, or migrate cleanly to a hardened Android WebView architecture with native Chrome Custom Tabs for OAuth and local offline asset caching.

1. The 5 Documented Reasons TWA Apps Get Rejected on Google Play

Trusted Web Activities (TWAs) allow developers to wrap Progressive Web Apps (PWAs) in an Android container. While convenient, Google Play review algorithms scrutinize TWAs intensely. Here are the 5 root causes of rejection:

1. AssetLinks Verification Failure

If the assetlinks.json file fails to verify, Chrome displays the browser URL address bar at the top of the screen. Reviewers flag this as an unverified browser wrapper and reject the release.

2. Minimum Functionality Policy

Google Play Developer Policy states that apps whose primary purpose is providing a webview of a website without added native functionality violate the Webview policy.

3. OAuth / Google Sign-In Redirects

When a user clicks "Sign in with Google" inside a TWA, Chrome security redirects the user outside the app to a browser tab, breaking the native user experience.

4. Lack of Offline Handling

If a tester opens the app in airplane mode and sees Chrome's "No Internet" dinosaur screen, Google rejects the app for failing basic quality and stability guidelines.

2. Migrating from TWA to Modern Hardened WebView Architecture

The most reliable long-term solution for web-based Android apps is migrating to a native WebView with native scaffolding: 

// MainActivity.kt - Production-Hardened WebView Implementation
package com.example.webapp

import android.os.Bundle
import android.webkit.WebResourceError
import android.webkit.WebResourceRequest
import android.webkit.WebView
import android.webkit.WebViewClient
import androidx.appcompat.app.AppCompatActivity

class MainActivity : AppCompatActivity() {
    private lateinit var webView: WebView

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        webView = findViewById(R.id.webView)
        webView.settings.apply {
            javaScriptEnabled = true
            domStorageEnabled = true
            databaseEnabled = true
            allowFileAccess = false // Security hardening
        }

        webView.webViewClient = object : WebViewClient() {
            override fun onReceivedError(
                view: WebView?,
                request: WebResourceRequest?,
                error: WebResourceError?
            ) {
                // Prevent white-screen by loading clean offline fallback
                if (request?.isForMainFrame == true) {
                    view?.loadUrl("file:///android_asset/offline.html")
                }
            }
        }

        webView.loadUrl("https://yourdomain.com")
    }

    override fun onBackPressed() {
        if (webView.canGoBack()) {
            webView.goBack()
        } else {
            super.onBackPressed()
        }
    }
}

Frequently Asked Questions

Does a WebView app need to complete the 12-tester closed testing rule?

Yes. All personal Google Play developer accounts created on or after November 13, 2023, must complete the 14-day closed testing requirement with at least 12 testers, regardless of whether the app is native Kotlin, Flutter, React Native, TWA, or WebView.

Why does my TWA show the URL bar on testers' devices?

If Chrome displays the URL bar, your Digital Asset Links handshake failed. The most common cause is including the local upload key SHA-256 fingerprint in assetlinks.json instead of the Google Play App Signing key fingerprint found in Play Console under Release > Setup > App integrity.
